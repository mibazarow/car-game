## Проект
- **Игра:** «Patrol Rush» — топ-даун погоня полицейского за убегающей машиной (Godot 4.x, macOS, оконный режим, узкое высокое окно **540×960**, 4 полосы).
- **ТЗ:** `CAR_GAME.md`.
- **Ориентация моделей:** верх +Y, перед (нос) −Z, смена полосы по X (см. CAR_GAME.md §6.2).
- **Godot установлен:** 4.7.2 (`/opt/homebrew/bin/godot`), рендер GL Compatibility.

## Текущий статус (кратко)
- Милстоун 2 + функциональная полировка: счёт за обгон трафика (+1), реальная цель-погоня (спускается/ловится, +10), постепенный рост сложности (каждые 50 очков +1 скорости). Верифицировано headless, игра запущена.

## ✅ СДЕЛАНО

- **RoadGenerator** (`scripts/road/road_generator.gd` + `scenes/RoadGenerator.tscn`): бесконечная 4-полосная дорога, процедурная, скролл по +Z со скоростью `GameState.speed`, рециклинг сегментов (покрытие Z ≈ +13..−13).
- **PlayerCar** (`scripts/player/player_car.gd` + `scenes/PlayerCar.tscn`): заглушка-бокс (BoxMesh 1.7×0.9×2.8, нос −Z, без поворота!), движение по полосам X ∈ {-3,-1,1,3}, плавное сглаживание, косметический крен (banking, rotation.z на Body), фикс на Z=8.
- **Main.tscn:** камера орто (projection=1, size=11, current=true, y=25, rotation.x=-90°) + DirectionalLight (иначе плоские материалы чёрные) + RoadGenerator + PlayerCar.
- **Верификация:** `godot --headless --quit-after` и `--scene Main --verbose` — ошибок нет.

### Милстоун 2 — геймплей-цикл (коллизии + очки + UI)
- **GameState (`autoload/GameState.gd`):** `add_score()`, `game_over()`, `reset_run()`, сигнал `score_changed`, рекорд сохраняется в `user://best.cfg`.
- **Коллизии:** трафик и цель стали `Area3D` (layers: трафик=2, цель=4), движение в `_physics_process`; у игрока `DetectArea` (mask=6): столкновение с трафиком → `game_over()`, нагон цели → `add_score(100)` + `respawn()` цели (случайная новая полоса). Игрок замораживается на game_over.
- **HUD (`scenes/HUD.tscn` + `scripts/hud.gd`):** счёт/рекорд сверху по центру, обновление по `score_changed`.
- **Game Over (`scenes/GameOverScreen.tscn` + `scripts/game_over.gd`):** затемнение + «GAME OVER», итоговый счёт/рекорд, рестарт (кнопка / Enter / R) → `reset_run()` + `reload_current_scene()`.
- **Main.tscn:** добавлены HUD + GameOverScreen.
- Прим.: в `player_car.gd` проверка цели через `is_in_group("fleeing")` (не `is FleeingCar`) из-за порядка загрузки. UI без `Container`-нод (Godot 4.7 headless их «теряет» — работают ручные якоря/оффсеты).

### Функциональная полировка (рост сложности + цель-погоня)
- **Счёт за обгон:** каждый проехавший мимо трафик-кар → +1 очко (`traffic_car.gd`, только в state=="playing").
- **Цель-погоня (сейчас — «вечная погоня», поимки НЕТ):** `fleeing_car.gd` закреплён вверху, вечно «убегает», перестраивается и **объезжает трафик** (реактивный дайв: если полоса занята машиной в окне опасности `DANGER_AHEAD=4/ BEHIND=1.5` — уходит в свободную полосу через `_pick_safe_lane()`; трафик в группе `traffic`). Поимка/очки за поимку **убраны** (систему поимки — сильно позже). У игрока осталась только авария от трафика.
- **⚠️ ГРАБЛИ КАМЕРЫ (важно для координат):** орто-`Camera3D.size` — это **диаметр** (полная высота), НЕ полувысота (`class_camera3d.rst`). При `size=16` видимая зона камеры (центр z=-2) ≈ **Z -10..+6**, а НЕ -18..+14. Поэтому `Z_POS=-13` у цели был **выше кадра → обрезался камерой** (машина существовала, но не рендерилась). Исправлено: `Z_POS=-8` (вверху кадра). При задании координат считать видимый Z = camera_z ± size/2.

### Трафик не проезжает сквозь друг друга
- **Следование за впереди идущим** (`traffic_car.gd`): `_car_ahead()` находит ближайшую активную машину в той же полосе впереди; если дистанция < `FOLLOW_DIST=6`, скорость ограничивается `min(speed_z, ahead.speed_z)` — машина не догоняет впереди идущую.
- **Запрет спавна поверх** (`traffic_spawner.gd`): `_lane_clear_at_spawn()` — спавн только в полосу, где нет активной машины в радиусе `SPAWN_SAFE_DIST=6` от точки спавна; если все заняты — пропуск тика.
- Поправлен баг условия полосы в `_car_ahead()` (не «следовать» за машиной соседней полосы).

### Окно + обзор вперёд
- **Авторазмер окна** (`GameState._size_window()`): высота = **75% высоты экрана** пользователя (через `DisplayServer.screen_get_size()`), ширина = портретное соотношение ×0.5625, окно по центру. Guard `screen==ZERO` (headless). Исправлен ошибочный `is_class("DisplayServer")` (всегда false → не ресайзил).
- **Камера отзумлена/сдвинута** (`Main.tscn`): `size` 16 → **24**, `position.z` -2 → **-6** → видимая зона ≈ **Z -18..+6** (вперёд видно сильно больше; игрок по-прежнему внизу). Синяя цель `Z_POS` -8 → **-14** (под новым верхом кадра).
- ГРАБЛИ: орто `size` = полный диаметр; видимый Z = camera_z ± size/2.
- **Рост сложности (`GameState`):** `speed` +`SPEED_STEP` за каждые `SCORE_PER_LEVEL` очков (сейчас **+0.4 каждые 250 очков**, потолок `SPEED_MAX=24`) — медленно и постепенно, через `_update_difficulty()` в `add_score`. `reset_run()` сбрасывает speed/уровень. Трафик пересчитывает `speed_z` каждый кадр → ускорение применяется к уже живым машинам.
- Все Godot-API сверены с `godot-docs/` (класс-референсы цитированы субагентами: @GlobalScope, SceneTree, Node, CharacterBody3D, Area3D).
